# 修复 MIDI 导入越界与钢琴窗音高边界

## 问题

1. 导入 MIDI 时有概率失败，报错形如 `data byte must be in range 0..127`。复现：大量音符落在 24–71、另有一个 120 的文件，自动移调选择 +11，120 变成 131，写回 `edited/<曲目>.mid` 时 `mido.Message(note=131)` 抛错。
2. 钢琴窗只覆盖 A0–C8（MIDI 21–108），而 MIDI 音高是 0–127。导入 0、12、21 会全部叠在最底行，108、120、127 叠在最顶行；上下移动被夹在 21/108，边界外的音符无法移动。

## 根因

- `find_best_transpose` 只按“能映射的按键数”选移调，不检查移调后是否仍在 0–127。
- `_build_note_entry` 不钳制移调后的音高，`write_notes_to_midi` 直接把越界音高交给 mido。
- 铺面常量 `MIN_PITCH=21`、`MAX_PITCH=108`，渲染、拖动、移调、音域阶梯都以此为界。

## 修复范围

- 自动移调只接受「所有音符移调后仍在 0–127」的候选；`_build_note_entry` 防御性钳制；`write_notes_to_midi` 跳过越界音符并记录警告。
- 铺面音高范围扩展到 MIDI 0–127：场景高度、键盘、音域框阶梯、拖动、方向键/八度移调边界同步更新。
- 键盘标签按标准音名显示 C-1 ～ G9；游戏键位映射仍只覆盖原有 28 键。

## 非目标

- 不改变按键映射表、播放数据、UI 布局。
- 不改变自动移调“优先覆盖更多音符”的评分规则，只增加范围约束。
