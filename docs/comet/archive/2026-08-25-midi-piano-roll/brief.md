# Outcome

在现有 PyQt5 工具（`gui.py`）的主窗口内新增一个「MIDI 铺面编辑」区域（不弹出新窗口）：在播放列表中点击已成功导入转换的曲目，即在该区域按需显示对应曲目的钢琴铺面（piano roll），并可对音符进行编辑（新增、删除、拖动改变音高/起始时间、拖动改变时长）。播放曲目时铺面上会出现随实际播放进度移动的播放线。编辑保存后会重新生成该曲目在 `play_code/*.json` 中的 `playback_data`（按键+延迟序列），从而实际影响游戏内自动演奏的内容。

# Scope

- 不新增独立弹窗；在主窗口现有右侧区域改为 `QTabWidget`，包含两个标签页：「🎼 铺面编辑」与现有「📋 操作日志」。切换标签不影响日志内容和现有日志输出逻辑。
- 按需显示、无需弹窗：
  - 在现有播放列表（`play_listbox`）中点击/选中一个曲目时，「🎼 铺面编辑」标签页内容更新为该曲目的铺面（懒加载：只在被选中时解析/渲染，不在导入时批量预渲染）。
  - 铺面视图组件是单一可复用的部件，随选中曲目切换显示内容，不创建新窗口实例。
- 铺面视图：
  - 纵轴覆盖钢琴全部 88 键（MIDI note 21 A0 至 108 C8），标准琴键黑白配色排列。
  - 横轴为时间轴（沿用现有秒为单位的绝对时间，不做小节量化）。
  - 音符渲染为矩形块：左边缘 = 起始时间，宽度 = 时长，纵向位置 = 音高。
  - 音高落在游戏按键映射表覆盖范围内（约 4 个八度，`build_music.py` 中 `base_note_mapping`/`sharp_notes` 定义）的音符与映射范围外的音符使用不同视觉样式区分。
- 音符数据来源：曲目导入转换时，除现有 `playback_data`（按键序列）外，额外从源 MIDI 直接解析出结构化音符列表（音高、起始时间、时长、音轨），仅覆盖当前用于游戏转换的音轨（`processed_tracks`，现状为前两条有效音轨）和已应用的移调（`transpose`）。该音符列表随完整数据文件一起保存（新增字段）。对不含该字段的旧格式文件，选中时铺面区域提示"需要重新导入该 MIDI 才能编辑"，不崩溃、不编造数据（对应 A7）。
- 编辑操作（仅在没有播放正在进行时可用，见下方播放线部分）：
  - 新增音符：在空白网格处点击，新增一个默认时长的音符（音高取点击位置最近的半音，起始时间取点击位置）。
  - 删除音符：选中后删除（Delete 键或右键菜单）。
  - 移动音符：拖动改变音高（纵向）与起始时间（横向）。
  - 调整时长：拖动音符右边缘改变时长。
  - 一次编辑一个音符；不要求多选/批量拖动、不要求音量（velocity）编辑。
- 播放线跟踪：
  - 点击▶️播放开始播放某曲目后，如果「🎼 铺面编辑」标签页当前显示的正是这条曲目，铺面上出现一条随实际播放进度实时移动的竖直播放线（基于 `JX3Player` 实际执行耗时，而非预估时长）。
  - 播放期间禁用新增/删除/拖动/调整时长等编辑交互，避免与正在进行的播放产生数据竞争；播放停止或完成后恢复可编辑。
  - 播放过程中切换到显示其他曲目的铺面，只是切换视图，不影响后台实际播放；切回到正在播放的曲目时播放线恢复显示在正确位置；播放线只在当前显示曲目与实际播放曲目一致时出现。
- 落地到游戏播放数据：
  - 保存编辑后，直接复用现有 `MidiToKeysConverter` 的音符→按键映射与分组逻辑，由编辑后的音符列表重新生成 `playback_data`、`note_statistics` 与 `statistics`，覆盖写回同一个 `play_code/<曲目>.json` 文件；原始导入的 `.mid` 源文件不被修改（重新从 `midi/` 目录导入同一文件会覆盖已保存的编辑）。
  - 映射范围外的音符可以在 88 键铺面中自由摆放/编辑，但不会出现在生成的按键序列里（与现有导入转换对无法映射音符的静默跳过行为一致）。
  - 播放列表刷新沿用现状（读取 `play_code/*.json`），无需改动。

# Non-goals

- 不实现撤销/重做（undo/redo）历史栈；未保存时切换所选曲目或关闭程序需提示是否放弃更改即可。
- 不支持多音符批量选择/拖动、不支持音量（velocity）编辑、不支持量化/吸附网格、不支持修改音轨选择或移调参数（这些沿用现有导入流程结果）。
- 不修改 `player.py` 的按键执行逻辑本身（仅新增进度上报，用于驱动播放线），不修改按键映射规则。
- 不新增"还原为原始 MIDI"功能（用户可通过重新导入达到同等效果）。
- 播放期间不支持编辑（见 Scope 中的播放线部分），不作为缺陷。

# Acceptance examples

- A1: 成功导入并转换一个 `.mid` 文件后，在播放列表中点击该曲目，无需任何弹窗，主窗口内「🎼 铺面编辑」标签页立即显示覆盖 88 键范围的钢琴铺面，已有音符按正确的音高（纵轴）与起始时间/时长（横轴）渲染。
- A2: 在铺面中拖动一个可映射音符改变其音高和起始时间，点击保存后，重新查看该曲目的 `play_code/*.json`，`playback_data` 反映了修改后的音高对应按键与新的时间间隔。
- A3: 在铺面中拖动一个音符的右边缘缩短/延长其时长，铺面上矩形宽度相应变化（可视化/编辑辅助）；保存后 `playback_data` 不因该时长调整而改变（游戏按键回放是点按模型，时长不改变按键与延迟），与调整前保持一致。
- A4: 在铺面空白处新增一个可映射音符，保存后 `playback_data` 中出现对应新按键，且 `statistics.note_count`/`key_count` 相应增加。
- A5: 选中一个已存在的音符并删除，保存后 `playback_data` 不再包含该音符对应按键，其余音符时间关系保持正确。
- A6: 将一个音符拖动到映射范围之外（如超出约 4 个八度的可映射区间），铺面上以区别于可映射音符的样式显示；保存后该音符不出现在生成的 `playback_data` 中（与现有静默跳过一致）。
- A7: 对一个由旧版本（不含结构化音符列表字段）生成的 `play_code/*.json` 在播放列表中点击选中，铺面区域给出明确提示（需要重新导入该 MIDI 才能编辑），不会崩溃或产生错误数据。
- A8: 铺面存在未保存的修改时切换选中到另一个曲目，或尝试关闭程序，工具会提示用户确认是否放弃未保存的更改。
- A9: 点击▶️播放开始播放某曲目，且铺面区域当前显示的正是该曲目时，铺面上出现随实际播放耗时移动的播放线；播放正常结束或被手动停止后，播放线消失或复位。
- A10: 播放进行中，铺面的新增/删除/拖动/调整时长交互被禁用；播放结束或停止后恢复可用。

# Constraints and invariants

- 音符列表解析与按键映射必须复用 `build_music.py` 中 `MidiToKeysConverter` 现有的音高→按键状态机逻辑（含升降号状态切换），不得引入第二套独立映射规则。
- 铺面的 88 键范围固定为 MIDI 21–108（A0–C8），与实际可映射的游戏按键范围（约 MIDI 36–83 附近的自然/半音集合）分开显示。
- 保存回写 `play_code/<曲目>.json` 时必须保持文件仍是合法的 `jx3_piano_complete` 结构（`type`/`version` 字段不变），并更新 `playback_data`、`note_statistics`、`statistics` 与新增的结构化音符字段，避免破坏 GUI 现有的"刷新播放列表"、"查看文件信息"逻辑。
- 不改变现有批量导入（`BatchConversionWorker`）的转换结果和 `.json` 输出结构中已有字段的含义。
- 播放线的进度上报来自 `PlayThread`/`JX3Player` 实际执行耗时（新增信号），不得依赖与实际按键节奏脱节的估算定时器。

# Decisions

- 铺面编辑区域是主窗口内嵌的标签页（`QTabWidget` 中的一个标签），不是独立弹窗；点击播放列表中的曲目按需切换显示内容，不创建新窗口实例。
- 音符数据来源于直接解析源 MIDI（复用现有 `processed_tracks`/`transpose` 结果），而非从已经压缩为按键字符串的 `playback_data` 反向还原，因为后者已丢失独立音符的音高/时长边界信息。
- 编辑保存会真实影响游戏演奏内容（回写 `playback_data`），而不是仅做可视化预览——这是本次需求的核心目的。
- 映射范围外的音符允许在 88 键铺面中编辑/摆放，但不会被写入 `playback_data`，并需要有视觉区分。
- 播放时展示实时播放线（基于播放线程实际耗时），并在播放期间禁用编辑交互，避免数据竞争。
- 不做撤销/重做栈；未保存时切换曲目或关闭程序需二次确认。
- 【Verify 阶段确认，2026-08-25】音符时长（duration）仅作为铺面上的可视化/编辑辅助（矩形宽度），保存后不影响 `playback_data`；`player.py` 的按键执行逻辑（点按模型）与 `playback_data` 结构保持不变，维持已确认的 Non-goals。原因：游戏按键回放当前是纯"点按"而非"按住"，`pydd.py` 虽已提供未使用的按住能力，但启用它需要扩展 `playback_data` 结构并修改 `player.py` 执行逻辑，用户明确选择不做此扩展。

# Verification expectations

- 通过对已知简单 MIDI 样本（少量音符、可控音高/时长）走通导入→在播放列表中选中曲目查看铺面→编辑（新增/删除/移动）→保存的流程，检查生成的 `play_code/*.json` 中 `playback_data`、`note_statistics`、`statistics` 与编辑结果一致；单独验证仅调整时长（不改音高/起始时间）保存后 `playback_data` 与调整前一致（A3）。
- 检查映射范围外音符的视觉区分与静默跳过行为（A6）。
- 检查旧格式（无结构化音符字段）文件的容错提示（A7）。
- 检查未保存时切换曲目/关闭程序的确认提示（A8）。
- 检查播放期间播放线跟踪与编辑交互禁用（A9、A10）——可通过检查 `PlayThread` 进度信号与铺面禁用状态的代码路径验证，无需真实连接游戏。
- 静态检查：`python -c "import ast; ast.parse(open('gui.py',encoding='utf-8').read())"`（及新增模块）确保语法正确；如项目引入了自动化测试，一并运行。
