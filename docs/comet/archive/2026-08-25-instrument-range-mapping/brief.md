# Outcome

在铺面编辑基础上新增「乐器音域框」：一个可拖动、可通过两个下拉框设置上下边界的黄色半透明覆盖层，覆盖当前显示曲目的钢琴铺面（横向贯穿整个时间轴），用于框定新乐器工具实际可用的键位区间（游戏全部 28 个自然音键位映射中的某个连续闭区间，并向下/向上各延伸 1 个半音以支持该区间边界音符的升/降半音操作）。播放时不再读取任何已保存的按键播放 JSON：直接基于当前铺面显示的音符（含铺面编辑）与当前乐器音域框的范围，在内存中生成按键序列并调用 DD.dll 触发播放。铺面音符编辑能力保留，但"保存"改为把编辑后的音符另存为一个新的 MIDI 文件（而不是保存 `play_code/*.json`）。播放列表也不再依赖 `play_code/*.json`，改为直接列出 `midi/` 目录下已导入的 MIDI 文件。

# Scope

- 游戏全部按键映射（`build_music.py` 中 `base_note_mapping`）共 28 个自然音键位，按音高升序排列为固定序列：`Z X C V B N M A S D F G H J Q W E R T Y U 1 2 3 4 5 6 7`（对应 MIDI 36–83 中的自然音）。乐器音域框的「最低映射」「最高映射」始终从这 28 个键位标签中选择（下拉选择，保证取值合法且低≤高，避免自由文本输入的校验负担）。
- 乐器音域框的实际音高覆盖范围 = `[最低映射音高 - 1, 最高映射音高 + 1]`（半音，MIDI 值），即在用户设定的闭区间基础上，下边界向下扩 1 个半音、上边界向上扩 1 个半音，用于覆盖该乐器工具通过游戏内升/降半音操作能达到的实际音域。
  - 例：默认区间 A（低1，MIDI48）～J（低7，MIDI59），扩展后为 MIDI 47～60，共 14 个半音（黑白键）。
  - 例：区间 V（倍低4，MIDI41）～3（高3，MIDI76），扩展后为 MIDI 40～77，共 38 个半音（黑白键）。（用户原始示例写的是 39，经过按半音精确计算应为 38；已按"向下/向上各延伸 1 个半音"这一明确规则计算，请在确认阶段核对这个数字是否符合预期。）
- 铺面编辑 Tab 顶部新增一行工具栏（位于铺面绘制区域上方，与既有的"💾 保存"按钮/未保存指示同一行或紧邻）：
  - 「显示/隐藏映射」按钮：切换乐器音域框在铺面中的可见性（纯视觉开关，见下）。
  - 「最低映射」「最高映射」两个下拉框：从 28 个键位标签中选择，默认 A / J（对应默认区间）。修改后音域框（若当前可见）的高度立即实时更新；音域框当前的范围值始终作为播放时的依据，与是否可见无关。
- 乐器音域框的可见性只影响铺面上是否画出这个黄色半透明矩形，不影响播放时使用的范围——播放永远使用当前生效的「最低映射/最高映射」设置（无论框体当前是否显示）。
- 拖动交互：在音域框可见时，从框体内部（非音符所在位置）按下并纵向拖动可整体上下移动音域框（低、高同步平移，宽度/跨度不变，移动会吸附到 28 个键位的合法位置上）；拖动过程中两个下拉框的值随之实时同步更新。音域框只能在 28 键位序列范围内移动（不能拖出 Z 以下或 7 以上）。铺面横向的完整时间轴始终被音域框覆盖（水平方向不需要拖动，视觉上无限延伸）。
- 每次在播放列表中选中（或重新选中）一首曲目时，乐器音域框的范围重置为默认值（A～J），可见性重置为隐藏；同一首曲目保持选中期间调整范围/切换可见性会保留，直到切换到其他曲目。
- 铺面音符编辑（新增/删除/拖动音高时间/拖动调整时长）能力保留，交互方式与既有实现一致；音域框与音符编辑共用同一铺面视图（框体内部非音符处拖动=平移音域框，框体外或非音符空白处点击=新增音符，音符本体=编辑音符，逻辑与既有铺面编辑一致，只是新增了音域框这一层）。
- 播放（▶️）逻辑变更：点击播放时，基于当前铺面上显示的音符（含铺面编辑的当前状态，无论是否已保存）与当前乐器音域框的扩展范围，在内存中生成一份按键播放数据（不写入磁盘文件），过滤掉音高落在扩展范围之外的音符（与既有的"映射范围外静默跳过"惯例一致，只是范围现在由音域框动态决定而不是固定的约 4 个八度）；随后调用现有 `JX3Player`/DD.dll 执行按键播放，播放线跟踪逻辑不变。播放不要求先保存。
- 保存逻辑变更（原"💾 保存"按钮）：点击保存时，把当前铺面上的音符（含编辑）写回为一个新的 MIDI 文件，保存到 `midi/` 目录，不覆盖原始导入的 `.mid` 文件；新文件保存成功后自动出现在播放列表中，并自动切换为当前选中项。
- 数据来源/播放列表变更：
  - 播放列表改为读取 `midi/` 目录下已导入的 MIDI 文件（不再读取 `play_code/*.json`）。
  - 导入 MIDI 时不再调用 `generate_complete_data_file` 生成/保存 `play_code/*.json`；导入只做校验（文件可被 `mido` 解析、至少含一条可用音轨/音符）与复制到 `midi/` 目录。
  - 选中某个 MIDI 文件时，沿用现有自动选轨（音符数最多的前两条音轨）与自动最佳移调（`find_best_transpose`）逻辑，在内存中解析出音符列表用于铺面显示，不落盘。

# Non-goals

- 不修改 `player.py` 的按键执行循环本身（`_execute_playback_data`）与按键映射状态机（`midi_note_to_key_sequence`）；仅新增一个允许直接传入内存数据（而非文件路径）的播放入口。
- 不清理/删除历史遗留的 `play_code/*.json` 文件（已存在的旧文件保留在磁盘上，但播放列表不再读取它们）；不删除 `play_code` 相关代码本身（`build_music.py` 中的既有方法保留，只是不再被 GUI 主流程调用）。
- 不覆盖原始导入的 `.mid` 文件；不提供"还原为原始 MIDI"或删除已保存副本的功能。
- 不支持音域框的自由拖拽跨越 28 键位序列之外的范围，不支持音域框宽度小于最小值（至少覆盖 1 个键位映射）。
- 不新增撤销/重做。
- 不改变 88 键铺面本身的音高范围（仍为 MIDI 21–108）。
- 不要求保存后的 MIDI 文件对所有第三方 MIDI 播放器/宿主完全兼容；只要求能被本工具自身（`mido`/`extract_notes`）重新正确解析。

# Acceptance examples

- A1: 选中一首已导入的 MIDI 曲目后，铺面顶部出现「显示/隐藏映射」按钮和两个映射下拉框（默认显示 A / J）；点击按钮后铺面上出现覆盖 MIDI 47～60（共 14 个半音／黑白键）范围、横向贯穿整个时间轴的黄色半透明框体。
- A2: 将「最低映射」下拉框改为 V、「最高映射」改为 3 后，音域框（若可见）立即更新为覆盖 MIDI 40～77（共 38 个半音／黑白键）的范围。
- A3: 音域框可见时，在框体内部（非音符处）按下并上下拖动，可整体平移音域框到合法的键位位置，两个下拉框的值随拖动实时更新；拖动到 Z 以下或 7 以上会被限制在边界。
- A4: 点击播放（▶️）后，不产生/不写入任何 `play_code/*.json` 文件；实际触发的按键序列只包含音高落在当前音域框扩展范围内的音符，范围外的音符被静默跳过（可通过检查生成的内存按键序列验证，无需真实连接游戏）。
- A5: 播放列表来自 `midi/` 目录下已导入的 `.mid`/`.midi` 文件，而不是 `play_code/*.json`；导入一个新 MIDI 文件后列表中出现对应条目，且不会在 `play_code/` 下生成新文件。
- A6: 选中曲目 A 并调整音域框范围后，切换选中曲目 B 再切回曲目 A，音域框范围重置为默认 A～J（不保留上次调整）。
- A7: 在铺面中新增/删除/拖动/调整某个音符后，无需保存即可直接点击播放，触发的按键序列反映编辑后的音符状态（含音域框范围过滤）。
- A8: 编辑音符后点击「保存」，`midi/` 目录下出现一个新的 `.mid` 文件（不同于原始导入文件名，且原始文件内容不变），播放列表自动刷新并选中这个新文件；重新选中它时铺面显示的音符与保存前的编辑结果一致（通过重新解析该新 MIDI 文件验证）。
- A9: 铺面存在未保存的编辑时切换选中到另一个曲目，或尝试关闭程序，工具会提示用户确认是否放弃未保存的更改（沿用既有确认机制，只是"保存"目标改为 MIDI 文件）。

# Constraints and invariants

- 28 个键位标签与音高的对应关系必须与 `build_music.py` 的 `base_note_mapping` 完全一致，按音高升序固定为：Z(36) X(38) C(40) V(41) B(43) N(45) M(47) A(48) S(50) D(52) F(53) G(55) H(57) J(59) Q(60) W(62) E(64) R(65) T(67) Y(69) U(71) 1(72) 2(74) 3(76) 4(77) 5(79) 6(81) 7(83)。
- 音域框扩展范围 = `[最低映射对应MIDI - 1, 最高映射对应MIDI + 1]`，必须按半音（MIDI 值 ±1）计算，不得按"28 键序列中的相邻标签"计算（两者在多数位置结果相同，但在 C/F、E/F、B/C 等自然半音边界之外的位置会不同；半音口径更贴合需求 2 中"支持升降半音操作"的初衷）。
- 播放时的按键序列生成必须复用 `MidiToKeysConverter` 现有的音高→按键状态机逻辑（`midi_note_to_key_sequence`），只新增"音高是否落在当前音域框扩展范围内"这一过滤条件，不得引入第二套独立映射规则。
- 播放数据全程在内存中生成并直接传给播放执行逻辑，不写入 `play_code/` 或任何磁盘文件。
- 保存为新 MIDI 文件时，只重写实际被铺面处理/编辑的音轨（`processed_tracks`）内容；源文件中未被处理的其他音轨、tempo/元信息尽量原样保留，不因保存而丢失（避免用户原始文件中的无关音轨/速度信息被静默破坏）。

# Decisions

- 乐器音域框的范围输入使用下拉选择（而非自由文本框），下拉选项固定为 28 个键位标签，按音高升序排列，强制最低 ≤ 最高。
- 乐器音域框默认范围为 A～J（低音区一个八度），每次切换选中曲目时重置为该默认值并隐藏；同一曲目保持选中期间的调整会保留。
- 音域框的可见性只是视觉开关，不影响播放使用的范围——播放始终使用当前生效的最低/最高映射设置。
- 拖动音域框只能整体平移（低、高同步移动，跨度不变），不支持通过拖动边缘调整跨度（跨度调整只能通过两个下拉框）。
- 扩展范围按半音（MIDI ±1）计算，不按 28 键序列的相邻标签计算。
- 铺面音符编辑能力保留（新增/删除/拖动音高时间/拖动调整时长），播放直接读取铺面当前状态，不要求先保存。
- 保存把编辑结果另存为新的 MIDI 文件（不覆盖原始导入文件），保存后自动加入播放列表并切换为当前选中项；未保存的编辑在切换曲目/关闭程序时仍会提示确认是否放弃（沿用既有的保存/脏状态确认机制，只是保存目标从 `play_code/*.json` 改为新的 `.mid` 文件）。
- 保存新 MIDI 文件时只重写已处理音轨的内容，其余音轨/tempo 信息原样保留。

# Verification expectations

- 构造一个已知简单 MIDI 样本，验证：选中曲目后音域框默认范围与半音扩展计算（A1）、修改下拉框后范围实时更新（A2）、拖动音域框平移与边界限制（A3）。
- 验证点击播放后不产生/不写入 `play_code/*.json`（A4），且实际生成的内存按键序列正确排除音域框范围外的音符、只包含范围内音符对应的按键（可通过直接调用生成按键序列的函数验证，不需要真实连接游戏/DD 驱动）。
- 验证播放列表数据源变化：读取 `midi/*.mid`，导入新文件后列表更新且不产生 `play_code/*.json`（A5）。
- 验证切换曲目后音域框范围重置为默认值（A6）。
- 验证编辑后无需保存即可播放，播放数据反映编辑结果（A7）。
- 验证保存生成新 MIDI 文件、不覆盖原文件、播放列表自动刷新并选中新文件、重新解析后音符与编辑结果一致（A8），以及未保存修改的确认提示（A9）。
- 静态检查：`python -c "import ast; ast.parse(open('gui.py',encoding='utf-8').read())"`（及改动的 `build_music.py`、`player.py`、`piano_roll.py`）确保语法正确。
