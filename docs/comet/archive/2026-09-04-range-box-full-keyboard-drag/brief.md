# Outcome

把「乐器音域框」从一个纯粹的"过滤窗口"（下拉框直接等于框体边界，拖动会同步回写下拉框）重新设计为两个互相解耦、各司其职的部分：

- **黄色框体本身**：完全由拖动控制位置（在铺面全部 88 键自然音范围内自由平移），代表"演奏时要从当前铺面的原始音符里，截取哪一段音高走向"（源音高选取窗口）。
- **「最低映射」「最高映射」两个下拉框**：不再随拖动同步变化，代表"实际演奏时允许使用的最低/最高按键"（目标按键范围）；两者的（自然音序列）位置差决定框体的跨度（高度）。

播放时，先按框体当前范围（含 ±1 半音扩展）筛选出落在其中的原始音符，再把这些音符整体移调（移调量 = 最低映射对应音高 − 框体当前低边界音高），移调后的音高再复用既有按键状态机映射为实际按键；移调后仍落在游戏 28 键实际映射范围之外的音符，继续按现有规则静默跳过。

# Scope

- 黄色框体新增独立的"低边界"状态，只能通过拖动改变；拖动仍然是整体平移（低、高边界同步移动，跨度不变），但拖动过程中不再回写「最低映射」「最高映射」两个下拉框的显示值（`instrumentRangeChanged` 信号不再驱动下拉框同步逻辑）。
- 「最低映射」「最高映射」下拉框的值发生变化时：按两者在扩展后自然音序列（52 项，MIDI 21~108）中的位置差，重新计算框体的跨度；保持框体当前低边界不变，只重新计算高边界；如果新的跨度会让高边界超出序列顶端（MIDI 108 附近），按现有拖动到边界时同样的钳制方式，把低边界适当下压，以完整容纳这个跨度（不截断跨度本身）。
- 新增播放前的移调步骤：移调量 = 「最低映射」当前对应音高 − 框体当前低边界音高（只用「最低映射」作锚点，「最高映射」的绝对音高不直接参与移调量计算，只通过它与「最低映射」的差值参与跨度计算）；筛选出的音符按这个移调量整体平移（保持音符间原有音程关系不变，不做按比例拉伸/压缩）。
- 移调后的音高，复用 `MidiToKeysConverter.midi_note_to_key_sequence` 现有的音高 → 按键状态机逻辑映射为实际按键；该状态机既有的"半音"处理方式不变——所谓半音，指框体边界处、无法直接用某个自然键按出、只能通过游戏内"+"（升半音）/"-"（降半音）这两个特殊功能键临时切换后按出、演奏完那一个音符后又立刻切回自然状态的音符，不等同于笼统的"黑键"。
- 播放时的筛选规则不变：只有原始音高落在框体当前范围（低边界 −1 半音 ~ 高边界 +1 半音）内的音符才会被选中、参与移调与播放；框体范围外的音符继续按现有规则静默跳过。
- 移调后，若某个音符对应的音高仍然落在游戏 28 键实际映射表（`base_note_mapping`/`sharp_notes`/对应降号推导，约 MIDI 35~84 ± 1 半音）之外，同样按现有"无法映射返回空按键列表"的行为静默跳过，不报错。
- 每次在播放列表中选中（或重新选中）一首曲目时，框体位置与两个下拉框都重置为默认值 A~J（对应 MIDI 48/59）；此时移调量 = 48 − 48 = 0，播放表现与本次改动前完全一致。
- 「显示/隐藏映射」按钮的可见性开关语义不变：只影响是否画出黄色框体，不影响播放时使用的筛选范围与移调量。
- 音域框可设置/可拖动的键位序列本身（52 项，覆盖全部 88 键自然音位置，原有 28 个游戏按键字母标签 + 新增音名标签）沿用上一轮已完成并验收通过的实现，不再变更。

# Non-goals

- 不新增通过拖动框体边缘单独调整跨度（高度）的交互；跨度只能通过「最低映射」「最高映射」两个下拉框的差值决定，框体本身只能整体平移。
- 不新增按比例拉伸/压缩音程的移调方式；移调统一是固定半音数的整体平移，音符间原有音程关系保持不变。
- 不在框体的源端筛选之外，再额外新增一层基于「最低映射/最高映射」的输出端过滤 UI 或提示；移调后仍无法映射到实际按键的音符，继续沿用既有的"无法映射静默跳过"机制，不新增独立的边界检查或警告。
- 不新增显示"当前移调量是多少半音"的额外 UI/标签。
- 不改变 `midi_note_to_key_sequence` 状态机本身的升/降号临时切换与复原逻辑、`sharp_notes`/降号推导规则。
- 不改变 88 键铺面本身的音高范围、既有的铺面音符编辑能力、保存为新 MIDI 文件的逻辑、播放列表数据来源、可见性开关的既有语义等无关行为。
- 不改变「最低映射」「最高映射」下拉框现有的文字标签、选项来源（仍是上一轮已完成的 52 项自然音序列）。
- 不新增撤销/重做。

# Acceptance examples

- A1: 音域框可见时，从框体内部（非音符所在位置）按下并拖动，框体在铺面全部 88 键自然音范围内整体平移到新位置；拖动过程中及拖动结束后，「最低映射」「最高映射」两个下拉框的显示值都保持不变（不再随拖动实时更新）。
- A2: 把「最低映射」下拉框改为 Z、「最高映射」改为 M（自然音序列中位置差为 6）后，框体的跨度（高边界 − 低边界，按序列位置差计算）变为 6；框体当前的低边界不变，只有高边界随之调整。
- A3: 在框体当前低边界已经很靠近铺面顶端（如 C8 附近）的情况下，把「最高映射」下拉框改为一个会让新跨度超出铺面顶端的值：框体的低边界会被自动下压，以完整容纳这个跨度（跨度本身不被截断），与当前拖动到边界时的钳制表现一致。
- A4: 构造一段音符（小星星前两小节：C4,C4,G4,G4,A4,A4,G4,F4,F4,E4,E4,D4,D4,C4，对应 MIDI 60,60,67,67,69,69,67,65,65,64,64,62,62,60），把框体拖动到低边界为 MIDI 60（键位标签 `Q`）、跨度覆盖到至少 MIDI 69 的位置，并设置「最低映射」= `Z`（MIDI 36）、「最高映射」= `M`（MIDI 47）后点击播放：生成的内存音高序列应为原音符整体下移 24 个半音的结果（MIDI 36,36,43,43,45,45,43,41,41,40,40,38,38,36，对应 C2,C2,G2,G2,A2,A2,G2,F2,F2,E2,E2,D2,D2,C2），音符间的原有音程关系保持不变（不发生拉伸/压缩），且这些移调后的音高都能在游戏 28 键实际映射表中找到对应按键（Z/B/N/V/C/X），实际生成非空的按键序列。
- A5: 在 A4 的基础上，把其中一个音符的原始音高改为落在框体当前范围（含 ±1 半音扩展）之外（例如把最高音改为 MIDI 90），点击播放：该音符被静默跳过，不参与移调和按键生成，其余音符表现不变，不报错。
- A6: 把「最低映射」改为一个使移调后音高落在游戏 28 键实际映射范围之外的值（例如把 A4 场景的「最低映射」改为一个非常低的值，使移调后的音高低于 MIDI 35），点击播放：这些音符按现有"无法映射返回空按键列表"的行为被静默跳过，不报错、不崩溃；若移调后没有任何音符能生成按键，弹出既有的"当前乐器音域范围内没有可播放的音符"提示。
- A7: 选中曲目、切换到其他曲目再切回后，框体位置与两个下拉框都重置为默认值 A~J（对应 MIDI 48/59）；此时点击播放，若不做任何拖动或下拉框调整，播放表现与本次改动前（移调量为 0）完全一致。

# Constraints and invariants

- 框体的跨度计算方式：`span_idx = 最高映射在自然音序列中的位置 - 最低映射在自然音序列中的位置`（序列位置差，不是半音数差），与既有的拖动吸附、跨度保持逻辑使用同一套自然音序列（52 项）和同一种"按序列位置数、不按半音数"的既有约定保持一致（这是本项目沿用至今的既有惯例，不在本次改动中改为按半音数计算）。
- 框体跨度变化时的钳制方向：保持"跨度本身不被截断，改为调整低边界"这一策略，与既有拖动时"若请求的位置会让高边界超界，则把低边界钳制到刚好能容纳当前跨度的位置"使用同一钳制方式，不引入新的钳制策略。
- 移调量只由「最低映射」当前对应音高与框体当前低边界音高的差决定；「最高映射」的绝对音高不直接参与移调量计算。
- 源端筛选（哪些原始音符被选中）与目标端映射（移调后音高 → 实际按键）必须严格分两步：先按框体范围（原始音高，含 ±1 半音扩展）筛选，再对筛选后的音符统一应用同一个移调量，最后才对移调后的音高调用现有 `midi_note_to_key_sequence`；不得把两步合并成一次范围检查，也不得对不同音符使用不同的移调量。
- 移调后的按键生成必须复用 `MidiToKeysConverter` 现有的 `midi_note_to_key_sequence` 状态机（含其升/降号临时切换、下一个自然音时复原的既有行为），不得新增第二套按键映射或按键状态机。
- 播放数据仍然全程在内存中生成，不写入 `play_code/` 或任何磁盘文件（沿用已有约束）。
- 框体自身的自然音序列（52 项、字母/音名标签）、拖动的整体平移语义（低高同步移动、不支持拖边缘调整跨度）、可见性纯视觉开关语义，均沿用上一轮已验收通过的实现，本次改动不重新变更这些部分。

# Decisions

- 黄色框体与「最低映射/最高映射」下拉框解耦：框体的位置只由拖动决定，下拉框的值只由用户下拉选择决定；两者不再双向同步。
- 框体的跨度（高度）由两个下拉框在自然音序列中的位置差决定；下拉框变化时保持框体当前低边界不动、只调整高边界，跨度超界时按既有钳制方式下压低边界。
- 拖动框体是唯一改变框体位置的方式，拖动结束后不回写两个下拉框的显示值。
- 播放时新增"筛选 → 移调 → 按键映射"三段流程：先按框体范围筛选原始音符，再整体移调（移调量 = 最低映射音高 − 框体当前低边界音高，保持音程不变），最后复用既有按键状态机映射；移调后仍无法映射到实际游戏按键的音符，静默跳过。
- 半音的定义：框体边界处、需要通过游戏内"+"/"-"特殊功能键临时切换、演奏完当前音符后立刻复原的那类音符，不等同于"黑键"这个笼统说法；这个定义只用于文档措辞的准确性，不改变既有状态机的实际行为。
- 不新增拖动边缘调整跨度的交互、不新增按比例拉伸的移调方式、不新增显示当前移调量的 UI；下拉框的文字标签和既有选项来源不变。

# Verification expectations

- 静态检查：`python -c "import ast; ast.parse(open('gui.py',encoding='utf-8').read())"`、对 `piano_roll.py`、`build_music.py` 同样执行，确保语法正确。
- 通过脚本级合成鼠标事件（不依赖真实显示/用户交互）验证：
  - 拖动框体后，两个下拉框的显示值（或其对应的底层 pitch 状态）保持不变（A1）；
  - 修改下拉框后，框体跨度按位置差重新计算，低边界不变、只调整高边界（A2）；跨度超界时低边界被下压、跨度本身不被截断（A3）。
- 通过直接调用移调后的播放数据生成函数（不需要真实连接游戏/DD 驱动）验证：
  - 小星星示例：框体覆盖 MIDI 60~69（或更宽），最低映射=Z、最高映射=M，生成的按键序列对应下移 24 个半音后的音高，音程关系不变（A4）；
  - 框体范围外的音符被静默跳过（A5）；
  - 移调后仍无法映射到实际按键的音符被静默跳过、不报错，必要时触发既有的"无可播放音符"提示（A6）；
  - 切换曲目后框体与下拉框重置为默认 A~J，移调量为 0，播放表现与改动前一致（A7）。
