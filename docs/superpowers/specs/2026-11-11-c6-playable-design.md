# C6 可弹（音域框高端边界）设计

- 日期：2026-11-11
- 状态：已批准（方案 1）
- 相关代码：`build_music.py`

## 意图与背景

黄色音域框高边界为 B5（MIDI 83）、「最低映射」为 `Z`（C2，MIDI 36）时：

- 移调量 = 36 − 36 = 0
- 筛选窗口 = 框体两侧各扩 1 个半音 → MIDI 35~84
- 低端 B1（35）已能通过 `-` + `Z` 播放
- 高端 C6（84）被 `midi_note_to_key_sequence` 静默跳过

`docs/comet/specs/instrument-range-mapping/spec.md:45` 声明状态机覆盖「约 MIDI 35~84」，
因此 84 缺失属于实现遗漏，不是规格限制。

## 目标

- C6（MIDI 84）在筛选窗口内时可实际发声，按键序列为 `+` `7`
- 保持既有升/降号状态切换与复原行为不变
- 与低端 B1（35）的对称性一致

## 非目标

- 不支持 C#6（85）及以上
- 不改变框体 ±1 半音筛选语义
- 不扩展游戏 28 键 `base_note_mapping` 的实体按键范围

## 选定方案

在 `MidiToKeysConverter.sharp_notes` 中新增：

```python
84: (83, True),  # C6 -> 高7#
```

理由：

- 与现有 37~82 的黑键/升号写法完全一致，复用现有状态机
- 自动处理前一个音是降号、后一个音是自然音时的状态复原
- 备选「通用高端分支」测试面更大，当前只有 84 一个音，收益不足

## 影响

- 走框体的播放路径：C6 不再被跳过
- 不走框体的直接 MIDI 转换路径：C6 同样不再被跳过（与规格一致）

## 验证

- 脚本断言：`midi_note_to_key_sequence(84)` 返回 `['+', '7']`
- 状态切换：C6 → B5 时 B5 序列以 `-` 开头（复原升号）
- 边界对照：35、36、83、84 的按键序列符合预期
- GUI 中放置含 C6 的音符，确认播放时实际按键为 `+` `7`
