# 设计探索摘要（Design）

change: `editor-ui-and-arpeggiate`

## 已确认（用户）

- 编辑模式禁用弹奏；演奏模式可弹奏。
- 删除按钮放在每首曲子行末，而不是列表右侧。
- 四个标签文案按需求改名。
- BPM 样式与下拉框一致；「演奏最高键位映射」之后换行。
- 新增「曲谱优化」，脚本来自 `release/谱子/arpeggiate.py`，需加入项目。
- 默认映射 Z / 7；黄框默认 C2～B2。
- 统一交互 UI。

## 现状事实

- 工具栏单行，BPM 是 `QDoubleSpinBox` 默认样式。
- 播放列表删除按钮在右侧；刷新时重建条目。
- `_sync_roll_mode()` 已统一模式状态，但不管弹奏按钮。
- 映射下拉来自 `get_natural_key_ladder()`：Z=36、7=83。
- 黄框范围由 `set_instrument_range(low, high)` 控制。
- 外部脚本按 tick 处理整份 MIDI：窗口/步长 1/32 拍，组内按音高展开，结束时间不变。

## 候选方案

1. 新增内存版 `arpeggiate.py`（窗口/步长 = 拍长/32，纯函数），画布新增 `arpeggiate_selected`，GUI 按钮调用。
2. `_sync_roll_mode` 增加 `play_btn` 启用规则。
3. `refresh_play_list` 用 `setItemWidget` 生成「名称 + 🗑」行控件，删除按钮绑定该行曲目。
4. 工具栏拆三行：动作行（曲谱优化）+ 第一行（标题/状态/弹奏/保存/模式/两个映射）+ 第二行（绝对键/量化/BPM）。
5. 为 `QDoubleSpinBox` 增加与下拉框相同的 QSS。
6. 默认映射 Z/7；黄框默认 36～47 与映射解耦。

## 备选与丢弃

| 备选 | 原因 |
| --- | --- |
| 直接调用外部脚本（子进程 + 临时文件） | 慢、依赖文件路径、无法只作用于选中音符 |
| 用委托绘制删除按钮 | 实现复杂，事件命中不如行控件直观 |
| 黄框范围继续跟随映射下拉 | 与「默认 C2～B2」需求冲突 |

## 风险

- 每行删除按钮误触 → 保留确认框、文件不删、可恢复。
- 琶音过短时结束时间与最小时长冲突 → 钳制起点、保持结束时间。
- 窄窗口两行布局仍可能挤压 → 允许收缩，后续可加滚动。
